# Reflection billboard consistency diagnosis

Candidate52's ordinary and opaque water-reflection captures were directly opened. The raw water pass contains a recognizable flame in the pool, while its ordinary fixed view has a weak warm core. To avoid treating8-bit PNG values as linear light, a new opt-in `-vesperHDRDiagnostic 1` reads the actual reflection target into linear RGBAFloat and writes EXR plus JSON, without changing the saved scene or normal rendering.

Actual52 full reflection target: R16G16B16A16_SFloat,1024x683, peak linear luminance15.09753, peakRGB(19.578125,14.5546875,7.28125),106pixels above luminance1 and38above4. Shader/runtime/missing errors0. HDR energy survives in the reflection target; clipping the entire reflection to LDR is not the cause. The strongest global peak is not proof that the specific screen-left core survives its local occluders or water coverage.

Code diagnosis: `AtmosphereFlame.FlameVertex` originally constructed a new billboard from each camera's inverse-view right/up axes. For the mirrored camera, up.Y changes sign. Thus a texture sample below the emitter center is placed above it in world space for the reflection, while the same sample is below it in the main view. This is a different physical quad and light-emitting position, not the planar image of the original flame. At the full camera elevation.72rad, the Y displacement between the two physical positions is `2 * localY * scaleY * cos(.72)`, with sign depending on localY. A lower core at localY=-.35 on a1.65m quad differs by about.868m vertically.

The existing VesperBillboard component and capture setup already orient the object's transform to the source camera. The pending source correction uses that actual object-to-world transform for both main and reflected renders. No radiance, water Fresnel, opacity, blur, light range, texture, layout or geometry changes are included in this first comparison. Candidate53 actual comparison is pending. It may reveal new legitimate occlusion where the corrected core belongs; native evidence must decide that.

PavingV15's earlier CPU footprint analysis correctly modeled the then-current shader, including its camera-dependent reflected quad. Its quantitative occlusion findings must not be reused as the new fixed-shader footprint. The single11mm slab translation remains preserved as a prior diagnostic; no broad floor rollback is authorized by this finding.
