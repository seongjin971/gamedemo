제안 외형은 얼굴과 머리카락이 보이는 천 튜닉·가죽 조끼·바지·부츠, 작은 가방·허리 주머니, 짧은 망토 또는 어깨 천이다. 소박한 칼집은 선택 사항이며 P1에는 무기를 추가하지 않았다. 전투 기능은 포함하지 않는다. P1 구현에서는 밤 안뜰 가독성을 기준으로 밤색 머리·밝은 튜닉·갈색 가죽·짧은 청록 어깨 천을 선택했다. 이는 구현상 디자인 선택이며 사용자가 정확한 정체성·색을 지정했다는 뜻은 아니다.

갑옷을 제거한 빈 몸체나 옷 재질만 바꾼 기사로 끝내지 않는다. 어깨 폭·장비 부피·노출되는 관절·천의 주름까지 초보 모험가 체형에 맞춘다. 제작 기준은 다음과 같다.

- 스킨 메시와 골격을 사용하며, 최소 동작은 대기·걷기·정지 전환과 이동 방향 전환이다. 이동 속도에 보폭을 맞추고 발 미끄러짐을 직접 확인한다.
- 위치 이동의 소유자는 이동 컨트롤러 하나로 정한다. 초기 애니메이션은 제자리 클립을 사용해 경로 이동과 이중으로 전진하지 않게 한다. Animator의 루트 모션 설정은 이 설계에 맞춘다. [Unity Animator 문서](https://docs.unity3d.com/Manual/class-Animator.html)
- 자체 제작 클립이면 단순한 Generic 골격을 우선 검토하고, 외부 Humanoid 클립 재사용이 실제로 필요할 때 해당 리그·리타게팅을 선택한다. 둘을 모두 구축하는 작업은 하지 않는다.
- 첫 캐릭터는 실제 천 시뮬레이션을 필수로 하지 않는다. 망토·가방은 골격이나 제한된 보조 움직임으로 만들고 관통과 과도한 흔들림을 확인한다.
- 성인/성별·정확한 얼굴·무기 디자인 등 요청에 없는 정체성을 확정 사실로 문서화하지 않는다. Blender와 필요시 허용된 생성 도구로 제작하되, 생성 결과도 토폴로지·리깅·Unity 렌더 검토를 거친다.

## 5. 맵 구성과 지원할 환경

최종 목표는 **P3·P4·P5의 세 기후 구역이 지형과 보행 경로로 이어진 하나의 맵**이다. 아래 규모는 개발 시작점 제안이며 확정된 월드 크기가 아니다. 기존 밤 안뜰과 전달 빌드는 보존한다. 안뜰과 새 맵의 입구 연결 방식은 후속 설계 항목이며, 필수 연속 이동 범위는 우선 P3↔P4↔P5다.

| 공간 | 첫 지원 조합 | 걷는 구역과 대표 장면 |
| --- | --- | --- |
| P3 낮의 물가 | 맑은 낮 또는 옅은 구름 | 약 60–90초의 주요 보행 동선, 완만한 경사, 짧은 다리, 강둑과 갈대. 물 높이는 하나로 시작하고 P4로 이어질 연결 길을 마련한다. |
| P4 비 오는 폐허 | 흐린 하늘과 강우 | 기존 폐허 자산을 활용한 확장 구역. 젖은 바닥 위 물튀김·처마 낙수·빗소리와 물가·고갯길로 이어지는 동선. 젖은 재질만으로 강우 구현을 완료 처리하지 않는다. |
| P5 눈 오는 고갯길 | 흐린 낮과 강설 | 약 60–90초의 주요 보행 동선, 적설 경계·바위·식생·눈발과 바람. 폐허에서 안개 낀 오르막을 거쳐 이어진다. |

낮의 물가는 물가와 낮 맵 요구를 함께 충족하는 제안이다. 독립된 대형 초원 맵이나 추가 낮 전용 구역은 이 계획에 자동 포함되지 않는다. 물가는 우선 육지·다리 보행으로 완성하며 수영·잠수는 제외한다.

각 구역은 정해진 기본 환경을 가지며, 연결 구간에서 플레이어 위치와 경계까지의 거리에 따라 점진적으로 혼합한다. 빛·하늘·안개·노출·바람·환경음·비와 눈의 밀도·젖은 표현을 함께 조율한다. 경계에서 멈추거나 되돌아갈 때도 상태가 튀거나 깜빡이지 않아야 한다. 전체 화면의 갑작스러운 색·밝기 변경으로 전환을 대신하지 않는다.

풀·흙·젖은 돌·서리·눈의 지면과 식생 변화는 실제 연결 지형에 배치한다. 화면 색과 강수 효과만 바꾸어 풍경 전환을 완료 처리하지 않는다. 이는 위치에 따른 세 기후 구역의 전환이며, 시간 경과에 따른 전 세계 날씨·낮밤·계절 시뮬레이션은 포함하지 않는다.

비는 카메라 주변 효과와 지면 반응을 사용하고 지붕·실내의 강우 제외 영역을 처리한다. 눈은 표면 방향과 턱에 맞는 정적인 적설 형태를 먼저 만들고 눈발을 더한다. 바닥 흰색 보정, 동적인 눈 쌓임·녹음·변형 지형, 모든 발자국의 영구 보존은 각각 별개 기능이다. 첫 확장에서는 정적 적설과 강설까지만 약속한다.

## 6. 필요한 최소 공통 구조

**캐릭터와 이동.** P2의 모험가·걷기·달리기와 AI Navigation 2.0.14 기반을 이어 쓴다. 세 구역과 연결 길의 이동 표면을 이어, 경계 너머를 클릭하거나 걷기·달리기 중 경계를 통과해도 경로가 끊기지 않게 한다. 내부적으로 Unity 장면이나 데이터 단위를 나누는지는 구현 선택이며, 플레이어가 경험하는 맵과 이동은 연속되어야 한다.

클릭은 실제 충돌 지면과 이동 가능 표면을 확인한다. 작은 범위의 표면 보정으로 벽 반대편·강 건너편·다리 아래로 잘못 이동시키지 않아야 한다. 도달 불가능한 클릭은 안전하게 거부한다. 장식 계단이 자동으로 보행 계단이 되는 것도 아니다. 보행 표면, 최대 경사와 단차, 캐릭터의 통과 폭을 별도로 구성한다.

**연속 구역 이동.** 공통 플레이어·카메라·입력을 유지한 채 연결 길을 걸어서 건넌다. 경계 통과 시 암전·순간이동·스폰 재배치·카메라 리셋·입력 잠금을 사용하지 않는다. 인접 구역은 경계에서 동시에 보이고 이동 가능해야 하므로 기존의 활성 구역 하나 제한을 새 맵에 적용하지 않는다. 필요한 콘텐츠는 접근 전에 준비하고, 멀어진 구역의 고비용 효과와 세부 묘사는 점진적으로 줄이거나 비활성화한다. 보이는 지형·그림자·날씨가 갑자기 사라지지 않게 한다. 대규모 오픈월드용 범용 스트리밍 플랫폼은 요구하지 않는다.

구역 데이터에는 공간 경계·연결 길·환경 혼합 범위, 이동 표면, 조명·하늘·안개·날씨·환경음, 주 수면과 세부 묘사 범위를 둔다. 공통 관리자가 환경 혼합을 조율하여 전역 조명·안개·반사 설정이 충돌하지 않게 한다. 비·눈은 카메라 주변 필요한 범위에서 처리하되 지붕 아래와 기후 경계의 공간 차이를 유지한다. 반사·효과·음원을 중복 생성하거나 경계에서 갑자기 끄지 않는다. R은 명시적으로 눌렀을 때 안전한 체크포인트로 복귀하도록 후속 설계하며 자동 경계 통과와 분리한다. 디스크 세이브·로드는 별도 범위다.

**카메라와 원경.** 현재 클릭·드래그·휠 조작 감각은 유지하되 플레이어 높이와 이동 거리를 따라가고, 근접 줌에서 캐릭터가 화면 밖으로 잘리는 문제를 확인한다. 기존의 제한된 회전 스타일을 유지한다. 걸어갈 수 있는 곳은 실제 지형으로 만들고 기존 원경 그림을 확대해 보행 구역으로 취급하지 않는다.

**렌더링.** 낮에는 태양뿐 아니라 간접광·하늘·안개·반사 환경·발광 강도와 재질을 함께 조정한다. 물가 수면은 수심과 물가 경계, 바위·기둥 접촉, 투명 물체 정렬을 확인한다. 기존 야간 바닥 셰이더와 반사를 그대로 복제해 강의 표현이 끝났다고 판단하지 않는다. 구역별 주요 수면 반사는 최대 하나로 시작한다.

## 7. 제작 순서와 단계별 완료 조건

| 단계 | 실제 납품물 | 다음 단계로 넘어가기 전 확인 |
| --- | --- | --- |
| P0 계획 | 이 문서와 채택·체크포인트 갱신 | 완료된 이전 계획 검토. 후속 사용자 지시로 P1 구현이 허용됨. |
| P1 초보 모험가 | 기존 안뜰의 별도 장면에서 새 캐릭터로 걷는 Windows 빌드 | 기본/회전/근접 구도에서 복장·실루엣, 대기→걷기→정지·회전, 발 미끄러짐·옷/가방 관통, 기존 이동·카메라와 성능 비교. |
| P2 높이와 구역 전환 | 작은 경사로·다리·장애물이 있는 임시 구역과 안뜰을 왕복하는 빌드 | 실제 지면 클릭, 물/벽/단차 차단, 왕복 3회, 스폰·R 초기화, 중복 플레이어/카메라·잔류 날씨·반사 상태 없음. 임시 지형 통과는 시각 완성 판정이 아니다. |
| P3 낮의 물가 + 연속 맵 기반 | 새 맵의 물가와 연결 길, 위치 기반 환경 혼합·연속 이동의 기반을 갖춘 빌드 | 낮 재질·원경·강둑·수면·다리, 두 환경을 혼합하는 짧은 연결 시험 구간의 양방향 이동. 시험 구간을 P4 완성으로 계산하지 않는다. |
| P4 비 오는 폐허 | 같은 맵의 물가에서 흐려지는 연결 길을 거쳐 걸어갈 수 있는 폐허 | 암전·위치 리셋 없는 P3↔P4 왕복, 강우·젖음·지붕 차단·환경음의 점진적 변화, 경계에서 정지·되돌아가기와 인접 구역 동시 표시 비용. |
| P5 눈 오는 고갯길 | 같은 맵에 오르막과 설원을 추가한 세 구역 탐험 빌드 | P4↔P5의 안개·비/눈·적설 경계·식생 전환, 전체 P3↔P4↔P5 연속 왕복, 지면 클릭·발 접지·카메라·효과 정리·성능 종합 검증. |

P1·P2 전달 상태는 상단의 최신 기록을 따른다. P3부터 하나의 연속 맵을 순차 확장하며 세 기후 구역의 최종 결합을 P5에서 검증한다. 단계 번호는 제작 순서이고 맵 파일 수를 뜻하지 않는다. 이번 사용자 지시는 목표·문서 갱신이며 P3–P5 구현 착수 지시는 아니다. 이후 구현이 허용되면 해당 범위에서 진행하고 동일한 작업에 대한 승인을 반복 요청하지 않는다.

## 8. 품질·성능 검증과 범위 관리

- 두 기후 경계 모두에서 걷기·달리기·경계 너머 클릭·정지·역방향 이동·반복 왕복을 검사한다. 순간이동·입력 잠금·카메라 튐·경로 단절이 없어야 한다. 좌표와 실제 이동을 함께 기록하고 내부 이동 함수 호출만으로 입력 검증을 대체하지 않는다.
- 연결 구간의 시작·중간·끝과 역방향을 실제 화면 및 연속 동작으로 검토한다. 조명·안개·하늘·강수·바람·환경음과 지면·식생 변화가 이어져야 하며, 효과의 중복·갑작스러운 출현/소멸·지붕 아래 강수 누출을 확인한다.
- 구역 중앙뿐 아니라 두 구역이 함께 보이는 경계에서도 정지·이동·회전·줌 성능과 접근 시 멈칫함을 측정한다. 먼 구역의 세부 묘사·날씨·반사·그림자 비용을 제한하되 보이는 풍경을 갑자기 끄지 않는다. 최신 P2의 약32FPS는 비교 출발점이며 세 구역 동시 표시의 성능 보장이 아니다.

- 실제 게임 카메라에서 캐릭터와 각 환경의 대표 구도를 먼저 정한다. 새 환경의 시안을 현재 채택된 VESPER 분위기와 맞추고 실제 Unity 캡처를 비교한다. 과거 concept 복제 점수를 새 물가/설원의 점수로 사용하지 않는다.
- 기본 비교 해상도는1536×1024로 유지한다. 기존 브라우저 slice 회귀 비교가 필요한 경우에만1037×739를 사용한다. 새 맵의 카메라 위치와 캡처 조건도 증거에 기록한다.
- 단계별 빌드·런타임 오류와 눈으로 확인한 결과를 따로 적는다. 준비된 시각 후보는 해당 브리프 기준으로 새 독립 검토를 받으며, 사용자 채택을 숫자로 대체하거나 임의의8점 획득까지 무기한 반복하지 않는다.
- 성능은 같은 Arc130V·해상도·API·설정에서 비계측 자연 루프로 정지/이동/회전/줌을 비교한다. 이전 실행과 환경이 달라질 수 있으므로 단계 착수 때 비교 기준을 다시 실행한다. 영상 캡처와 GPU 원인 분석은 별도 실행으로 한다.
- 제안하는 회귀 기준: 같은 조건에서 직전 플레이 빌드보다 평균FPS가10% 넘게 낮아지거나 p95프레임 시간이10% 넘게 늘면 다음 범위를 얹기 전에 원인을 점검한다. 새 환경도 날씨/수면 효과의 전후 및 경계의 인접 구역 동시 표시 비용을 비교한다. 이 수치는 검토용 개발 기준이며 이미 검증된 성능 보장이 아니다.
- 60FPS는16.7ms/frame의 목표다. 최신 P2 측정은32.02~32.47FPS이며 과거 candidate58의 약23ms 측정과 구분한다. 경계의 인접 구역 표시·그림자 범위·원경 세부 묘사·날씨 오버드로·반사 비용을 먼저 관리한다. 프레임 수만 맞추기 위해 채택된 외형을 임의로 낮추지 않는다.
- 자동 동작은 실제 입력 검증과 구분한다. 향후 구현 때 Windows Computer Use 연결을 다시 확인한다. 연결이 계속 불가하면 그 한계를 기록하고 자동 증거를 직접 조작 결과로 보고하지 않는다. 기존 사용자 권한을 반복 요청하지 않는다.

이번 확장의 기본 플레이는 탐색이다. 전투·적·퀘스트·레벨업·인벤토리 시스템·장비 교체·점프·수영·전체 오픈월드·실시간 계절 전환은 현재 요청에서 구현 범위로 정해지지 않았다. 필요한 추가 기능은 기존 목표와 분리해 범위를 판단한다.
