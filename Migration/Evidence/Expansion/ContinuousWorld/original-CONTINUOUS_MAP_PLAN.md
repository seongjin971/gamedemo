# VESPER — 통합 맵 구현 계획

작성: 2026-09-10. 상태: **시안 방향 사용자 동의 / 구현 계획 작성 / 구현 미착수**.

사용자는 Higgsfield 조감도에 “오케이 좋다”라고 응답하고, 이를 하나의 맵으로 구현할 계획을 요청했다. 동의한 방향은 세 기후 구역이 연결되는 풍경과 구성이다. 이미지의 모든 치수·오브젝트·이동 경로가 확정되었다는 뜻은 아니다. 이 문서는 EXPANSION_PLAN.md 5~8절을 실행 가능한 작업 단위로 구체화한다. 이번 작업은 계획 문서 작성까지다.

## 1. 만들 결과

**물가 → 숲과 젖은 길 → 비 오는 폐허 → 안개 낀 오르막 → 눈 오는 고갯길**을 한 캐릭터로 왕복하는 탐험 맵을 만든다. 주동선 하나에 짧은 전망 공간과 옆길을 두고, 첫 버전의 편도 보행은 약 3~5분을 시작 제안으로 삼는다. 정확한 크기와 시간은 실제 캐릭터 속도로 지형 초안을 걸어보고 정한다. 기존 구역별 60~90초 제안도 그 결과에 맞춰 조정한다.

| 공간 | 시야와 지형 | 플레이에서 확인할 것 |
| --- | --- | --- |
| P3 물가 | 낮은 강둑, 갈대, 바위, 작은 석교, 넓은 육지 | 입구에서 진행 방향이 보이고 물가 가장자리와 다리까지 클릭 이동 가능 |
| P3→P4 연결 길 | 완만한 굽이, 나무와 바위, 점차 젖는 흙과 석판 | 길이 끊기지 않으며 흐려지는 빛·안개·빗소리를 느끼면서 폐허가 나타남 |
| P4 폐허 | 기존 고딕 석조 분위기의 무너진 예배당과 작은 안뜰, 물웅덩이 | 비 오는 열린 공간과 비를 피할 수 있는 덮인 공간을 구분 |
| P4→P5 오르막 | 굽은 경사길, 옅은 안개, 드문 식생, 서리와 눈의 증가 | 높이 변화 중 발 접지·카메라·클릭 경로 유지 |
| P5 고갯길 | 눈 덮인 바위와 침엽수, 석조 이정표, 마지막 전망 공간 | 도착 지점을 알아볼 수 있고 같은 길로 자연스럽게 귀환 가능 |

조감도의 압축된 구도는 공간 관계의 참고로 삼는다. 실제 플레이에서는 연결 길에 충분한 길이와 굽이를 두어 비와 눈의 경계가 붙여 놓은 배경처럼 보이지 않게 한다. 기존 밤 안뜰은 이번 통합 맵 밖에 보존한다.

## 2. 구현 구조와 자산 제작

- 첫 버전은 **Unity 장면 하나에 세 구역과 두 연결 길을 함께 배치**한다. 플레이어·카메라·입력·환경 조율기는 하나씩 유지한다. 구역별 오브젝트 묶음으로 편집하고, 처음부터 장면 스트리밍 시스템을 만들지 않는다. 성능 측정으로 필요성이 입증될 때만 내부 분할을 검토한다.
- 현재 P2World는 콘텐츠 활성 전환, 암전, ResetPosition, 카메라 Enter를 수행한다. 새 월드에서는 이 전환기를 사용하지 않는다. P2의 걷기·달리기·클릭 보정·카메라 동작을 기반으로 하되, P2World 의존성과 고정된 구역 가정은 확장 전용 코드에서 분리한다.
- 지형은 넓고 연속적인 보행 바닥을 먼저 만든다. 표면 메시, 클릭용 충돌 표면, 이동 가능 영역을 같은 지형 정의에서 구성한다. 석판 틈 같은 시각 장식이 이동망을 잘게 끊지 않게 하고, 실제 벽·수면·낭떠러지·과도한 경사는 명확하게 구분한다.
- 세 구역 전체의 경로 연결을 먼저 만든다. 작은 클릭 보정은 같은 높이·같은 보행 표면 안에서만 허용하고, 벽 너머나 다리 아래 표면으로 옮겨 붙이지 않는다. 새 경사·단차에서 기존 접지 판정과 이동 중 몸체 충돌의 부족한 부분을 검증하고 필요한 방어를 추가한다.
- 기존 캐릭터·애니메이션·석조·바위 자산은 호환성을 확인해 재사용한다. 신규 제작은 강둑과 수면, 식생, 연결 지형, 눈 덮인 바위·소나무 등 부족한 요소에 집중한다. 공유 재질을 바꿔 기존 장면에 영향을 주지 않도록 확장용 변형을 만든다.
- Higgsfield 이미지는 구도·재질·분위기 참고로 사용한다. 실제 지형과 충돌은 Unity에서, 필요한 입체 자산은 Blender 등으로 제작한다. 외부 생성 자산은 개별 원본·출처·비용을 기록하고 Unity에서 크기·재질·성능을 확인한다.
- 실제 게임 카메라의 물가·폐허·고갯길 대표 구도와 두 경계 구도를 고정한다. 높은 조감도와 게임 화면을 같은 구도로 오인해 평가하지 않는다.

## 3. 날씨와 풍경의 연속 변화

환경 조율기 하나가 플레이어 위치와 연결 구간 안의 진행도를 사용해 세 환경 설정의 가중치를 계산한다. 경계에서 멈추거나 되돌아가도 같은 위치에서 같은 환경으로 부드럽게 돌아와야 한다. 이동 속도에 따라 변화량이 튀지 않게 한다.

| 항목 | 구현 방향 |
| --- | --- |
| 빛·하늘·노출·안개 | 공통 태양과 환경 설정을 완만하게 혼합. 구역마다 서로 다른 태양을 동시에 켜지 않음 |
| 비·눈 | 카메라 주변의 제한된 효과 범위에 공간별 강수 마스크를 적용. 비와 눈의 연결 구간은 짧은 혼합을 허용하되 맑은 물가나 지붕 안으로 새지 않게 함 |
| 지면과 식생 | 풀→흙→젖은 돌→서리→적설을 실제 지형과 재질에 위치별로 배치. 플레이어가 이동한다고 먼 물가 전체가 눈으로 변하지 않음 |
| 소리 | 물소리·바람·빗소리의 음량을 연속 조절. 국소 음원은 실제 위치에 배치 |
| 원경 | 다음 구역의 지형과 식생을 미리 보이게 하고 굽이·바위·안개로 연결. 전역 환경 혼합 때문에 먼 맑은 구역까지 한꺼번에 어두워 보이는 현상도 검토 |

수면은 첫 버전에서 한 높이의 주 수면으로 시작한다. 눈은 정적 적설과 눈발을 지원한다. 동적 적설·융해·계절 순환은 이 구현 목표에 포함하지 않는다.

## 4. 제작 순서와 단계별 납품

| 순서 | 범위 | 납품과 다음 단계 진입 기준 |
| --- | --- | --- |
| A. 전체 길과 환경 시험 — P3 기반 | 세 구역과 연결 길 전부를 단순 지형으로 배치. 기존 캐릭터, 연속 경로, 높이 추종, 카메라와 최소 날씨 혼합 연결 | 시작부터 끝까지 왕복하는 첫 실행 빌드. 양 경계의 클릭·달리기·정지·회귀와 실제 입력 확인. 아름다운 맵의 완성으로 보고하지 않음 |
| B. 물가 완성 — P3 | 낮 조명, 강둑·수면·석교·식생, 폐허 방향 연결 길 전반부 | 물가의 실제 게임 구도와 보행 검토. 나머지 구역 초안은 계속 연결된 상태 유지 |
| C. 폐허와 비 — P4 | 폐허의 구조·젖은 재질·강우·지붕 차단·소리, 물가와의 경계 완성 | 물가↔폐허 양방향 이동 중 풍경과 날씨의 연속성, 실내외 강수, 경계 성능 확인 |
| D. 고갯길과 눈 — P5 | 경사와 전망 공간, 바위·침엽수·적설·강설, 폐허와의 경계 완성 | 높이 변화와 눈 경계 검토. 세 구역 전체를 최종 지형에서 연속 왕복 |

첫 구현 작업 단위는 A다. 세 구역의 전체 보행 초안을 먼저 준비하므로 마지막에 맵을 붙이면서 경로·높이·카메라가 깨지는 위험을 일찍 확인할 수 있다. P3의 전체 지형 초안은 P4·P5의 시각 완성이 아니다. 단계별 실행 빌드와 증거를 남기며 기능 완료, 시각 검토, 사용자 수락을 각각 기록한다.

## 5. 검증과 성능 기준

- **바닥 클릭:** 세 구역과 연결 길에서 화면상 보행 바닥을 구역별로 고르게 클릭한다. 중앙만 검사하지 않고 가장자리·나무 옆·석교·경사 시작과 끝·장식 틈을 포함한다. 클릭 수신→광선 적중→목표 보정→완전한 경로→실제 도착을 연결해서 기록한다.
- **이동 안전:** 벽·몸통·깊은 물·절벽의 거부, 다리 위/아래 오인, 단차와 경사, 달리기 중 접지와 몸체 관통을 검사한다. NavMesh 연결 검사만으로 이동 중 안전을 통과 처리하지 않는다.
- **연속 이동:** 전체 왕복 3회와 두 경계 각각의 정지·역방향 이동·빠른 반복 진입을 확인한다. 암전·스폰 재배치·입력 잠금·카메라 초기화가 없어야 한다.
- **눈으로 확인:** 세 대표 구도와 두 연결 구간의 시작/중간/끝을 실제 플레이 영상으로 검토한다. 비·눈·반사·그림자 출현, 노출 튐, 원경 변화, 캐릭터 가림을 확인한다.
- **실제 입력:** 마우스와 사용자 트랙패드의 클릭·드래그·휠·Shift 조작은 합성 입력과 별도 기록한다. 자동 검증 통과를 사용자 조작감 수락으로 바꾸지 않는다.
- **성능:** 착수 때 P2를 동일 기기·1536×1024·API·설정에서 다시 측정한다. 새 맵은 각 구역과 두 경계의 정지·이동·회전·줌에서 평균 FPS, p95 프레임 시간, 접근 시 멈칫함을 기록한다. 기존 약32FPS는 과거 비교값이며 새 맵의 성능 보장이 아니다.
- **비용 관리:** A부터 세 구역이 함께 있을 때의 비용을 확인하고 B~D에서 수면·그림자·날씨를 각각 켜고 꺼 병목을 분리한다. 먼 식생과 메시의 세부 수준, 그림자 거리, 국소 강수와 제한된 반사를 우선 조정한다. 보이는 풍경이나 이동 표면을 갑자기 끄지 않는다.
- **진행 판단:** 기존 계획의 평균 FPS 또는 p95 프레임 시간 10% 회귀 기준을 적용한다. 큰 회귀나 입력·이동 결함이 있으면 해당 단계에서 원인을 해결한 뒤 다음 시각 요소를 얹는다. 60FPS는 별도 목표이며 사전 달성을 약속하지 않는다.

## 6. 파일과 종료 지점

구현 시 제안 경로는 `Assets/Vesper/Expansion/ContinuousWorld/`, 장면은 `Assets/Vesper/Scenes/Expansion/VesperContinuousWorld.unity`, 빌드는 `Builds/VesperContinuousWorld/`, 실행기는 `PLAY_VESPER_WORLD.cmd`, 증거는 `Migration/Evidence/Expansion/ContinuousWorld/`다. 아직 생성된 구현 파일은 아니다.

기존 candidate58, P1/Mixamo/Run, P2와 P2ClickFix의 장면·빌드·실행기 및 공유 자산을 보존한다. 현재 P2의 사용자 직접 수락 대기 상태도 유지한다. 안전 정지 요청이 오면 현재 단계의 저장 가능한 상태와 재개 문서를 남긴다.

최종 목표는 세 기후 구역을 자연스럽게 걸어 다니는 하나의 플레이 가능한 탐험 맵이다. 전투·퀘스트·인벤토리·수영·대규모 오픈월드 시스템은 별도 작업으로 둔다.
