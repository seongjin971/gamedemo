# 저장 영상 끊김 진단 — 2026-09-11

사용자는 Windows 캡처/Xbox Game Bar 계열로 녹화했으며, 플레이 중에는 정상이었고 저장된 영상만 끊긴다고 답했다. 게임·실행기·녹화 설정과 원본 영상은 변경하지 않았다.

## 확인한 사실

- 최근 영상 `C:/Users/brian/Videos/화면 녹화/화면 녹화 중 2026-09-11 205624.mp4`의10초 원본 프레임을 직접 확인했다. 현재L09 게임 영상이다.
- 실제파일: **2880×1800, H.264, 30FPS,59.5초,1,785프레임,약162.6MB(155.0MiB)**. FHD1920×1080보다픽셀수2.5배다. 당시FHD 게임 실행은 확인됐지만 녹화 파일은 모니터의 기본 해상도로 저장됐다.
- 원본패킷 표시 간격은 모두33.33ms다. 파일 타임스탬프가 크게 뛰는 문제는 발견되지 않았다. [타이밍](timing.json)
- 전체영상을160×100 회색조로 디코딩해 인접프레임의 평균밝기차이를 분석했다. 정확히일치하는축소프레임0, 평균차이0.10/255미만의거의같은프레임355개(약19.9%). 보통인접프레임의중앙값차이는4.06/255다. 5초구간별로도22~36개의거의같은프레임이관찰됐다. [분석값과주의점](analysis.json)
- 큰움직임이다시이어지기직전에약0.067초동안거의같은화면이유지되는구간도13.333초,27.433초,29.300초,32.600초근처에있다. 정지화면과압축의영향을완전히분리한손실프레임계수는아니므로355개를정확한캡처손실수로단정하지않는다.
- 현재게임코드는targetFrameRate120/vSync0이다. 앞선57.97~90.38FPS는1536×1024에서녹화없이측정한값이다. FHD녹화중성능으로확대할수없다.

## 판단

영상자체에서움직임이잠시반복되는흔적이있어재생기만의문제보다캡처/인코딩단의불균일한화면갱신을먼저의심한다. 2880×1800전체화면캡처와120FPS를목표로하는게임이동시에실행될때의GPU/메모리부하가가능한원인이다. GPU인코더지연로그나동일조건재녹화는없으므로특정하드웨어병목또는전체화면모드를단일원인으로확정하지않는다. 30FPS영상은원래60FPS플레이보다덜부드러울수도있다.

폴더/파일명은Windows 캡처도구 녹화형태에가깝고기본Videos/Captures에는파일이없었다. 앱정체는이것만으로확정하지않는다. Microsoft문서상Win+Shift+R은캡처도구,Win+Alt+R은Xbox Game Bar녹화다.

다음녹화에서는**녹화출력까지1920×1080,30FPS로맞추고**짧은움직임을먼저확인하는것이우선이다. OBS를사용한다면게임캡처와Intel QSV하드웨어인코딩을검토할수있다. 단순FHD재압축은파일/재생부하를줄일수있지만누락된움직임을복원하지는않는다. 이번진단에서영상재압축·보간·설치·설정변경·새녹화는하지않았다.
