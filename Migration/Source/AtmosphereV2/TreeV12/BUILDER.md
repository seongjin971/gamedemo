# TreeV12 anatomy source package

Input is the frozen TreeV11 art-directed textured derivative. V11 originals and every existing derivative file are protected by hashes in protected-v11-hashes.json. Only TreeV12 files are authored. No Unity or external asset API changes occur.

Run build_tree_v12.py with Blender 5.2.1 --background --threads 3. The default rebuild renders all eight before/after frames. Final revision rerender used TREE_V12_SKIP_BEFORE=1 to reuse the unchanged matched before rig/images from pass2 and render only the four new after frames. Run validate_tree_v12.py with the Blender bundled standalone Python (NumPy is required).

The four selected broad fork regions use an 18% maximum perpendicular contraction with gradual transitions through their outer segments. Fine twig endpoints and overall spread are retained. A surface-neighborhood analysis finds isolated short convex spur sites in those broad regions and selects every third site by ranked prominence; only those neighborhoods retract. This is an explicit local-selection approximation to one-third of short bark spikes, not a claim that every bark feature is semantically classified.

Four unequal root corridors are retained from the existing surface. Their low parts extend radially by up to35% and compress vertically by up to35%, turning the steep original foot into lower buttresses. The intervening fringe sinks below the floor and the terminal radial portion disappears below local Y=0. Geometry remains present below the paving; it is not cut off or deleted. The source local origin, top height6.34, width6.3 and XZ placement are retained. Minimum Y decreases because of buried geometry; do not rescale or vertically recenter the mesh from its total AABB. Existing scene Transform and the root's -20-degree local yaw should remain.

Native JSON conversion is Blender (-x,z,-y), triangle [0,2,1] exactly once. FRONT preview corresponds to native local +Z viewer. UV coordinates remain exact per triangle against V11; white vertex colors leave bark texture color to the shader. Use the existing V11 downloaded texture maps. Root owns darker wood material and paving contact pockets; this package does not change them.

The final approach uses continuous spatial fields across all source pieces and UV seams. A positive deformation Jacobian is checked at each original vertex. Independent QA checks strict positive normal alignment in native Unity convention and separately reports source-to-result face rotation. A face rotating more than90 degrees relative to its old sliver normal does not alone establish inside-out geometry; volume orientation is measured by the Jacobian. The rejected graph-based limiter had moved adjacent source pieces inconsistently and is not used. Normals use a minimum correction toward the face hemisphere on exceptional source triangles, avoiding unnecessary full flat-face highlights. Clean before and after views share the same normal policy.

The before/after studio previews use identical lights and a matte roughness0.82 override to expose geometry; this override is applied equally and is not saved into the delivery blend or any Unity material. A thick review ground ends at local Y=0 and hides buried tips. Four views are front, two elevated off-axis views, and root close-up. They approximate supported oblique usage without claiming exact native camera reproduction or unrestricted360 coverage.

Rejected first pass is preserved under rejected-pass1: numeric normal QA alone missed actual local face folding; the direct preview caught it. Its root fringe also remained too skirt-like. The over-conservative second pass is preserved under rejected-pass2: measured median fork shrink fell to0.7?2.2%, and graph-local limiting created seam gaps. Neither rejected folder is suitable for integration.

`measure_root_footprint.py` writes actual native-local XZ hulls for Y0.12?0.7 and its three sub-bands, maximum origin radius, and four measured near-ground root vertices. These root-only envelopes intentionally exclude the crown. Convex hulls still cover empty spaces between individual roots and are evidence rather than an automatic collider prescription. `root-contact-hints.json` contains design directions only; final measured contact data is separate.

Final supported-view renders are completed directly from the saved derivative blend using render_final_tree_v12.py; that script neither exports nor modifies geometry. Root foot polygon units are native-local meters. The ordered hull vertices are counterclockwise in the numerical XZ plane, with no duplicate closing point. Actual root-contact vertex Y values are0.005?0.013m; groundProjection sets only Y to0 for a contact-pocket hint. Their positions are not assumed to coincide with existing paving gaps.
