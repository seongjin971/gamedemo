# Code-only cap normal assessment

Requested after root inspected V13 textured full and neutral close. No geometry, normals, UVs or indices in the stable V13 JSON have been changed, and no derivative has been generated. Any derivative follows candidate47 feedback and a new coordinated render slot.

Area-weighted cap-only smoothing is a plausible targeted correction for the visible fan highlights. V13 currently exports flat normals for each actual cap triangle. The bounded scan residual changes the triangle slopes by small unequal amounts, so their lighting exposes the ear-clipped/fan tessellation. Averaging each shared cap position's adjacent cap face-cross vectors would soften that lighting discontinuity while retaining the underlying stone's independent plane. Each stone is a separate smoothing domain; no averaging crosses soil gaps or neighboring bodies.

The derivative should classify cap triangles from each body's `cap_polygon_world_xz` and its top-side vertices, rather than use a global normal-Y threshold that might also include shallow bevels. Group cap vertices by body id plus exact position and UV. For each group, sum the adjacent cap face cross products and normalize. Assign the resulting normal only to cap-corner copies. Keep bevel, side and bottom normals unchanged; if any exported index is shared across those classes, duplicate that vertex for the cap before assignment. The perimeter then retains the hard cap-to-bevel break even though the cap's internal triangulation is smoothed.

For an initial diagnostic, preserve position/UV/color values and triangle order exactly and change only eligible normal entries where the current vertex split permits it. Do not combine vertices or reduce the exported vertex count in the same experiment. That keeps a direct causal comparison between the stable flat-normal asset and the normal derivative.

Require finite unit normals and positive dot(face-cross, sum of corner normals) for every triangle after smoothing, as well as exact preserved geometry/source hashes and unchanged closed volumes/coverage. Area weighting is not guaranteed to pass automatically on a very thin or sharply sloped residual triangle. If such a face fails, retain an explicit local hard split or crease restriction; do not flip indices or weaken the positive-dot gate. A failed normal candidate remains separate and unimported.

Expected benefit is less fan-shaped specular/diffuse banding within a broad cap. It will not remove physical microheight ridges, geometry shadows from those ridges, original photo cracks, source course repetition, too-small source stones or the scene's water BRDF. It should retain independent stone plane changes and hard worn perimeters because those are separate averaging domains. Those expectations are code analysis, not a rendered or native result.
