# Stair source integration contract

Candidate source; not automatically adopted. Root performs all Unity Editor API changes.

1. Read `stair-removal-manifest.json`. Verify `bridge_sha256` against the exact input `Assets/Vesper/Import/unity-scene.json` bytes. Each row contains the original, unfiltered `node.instances` index, node UUID, geometry UUID, material UUID, and all source position/quaternion/scale/color floats. Check all of these before omission. A match must remove one original source component, never a whole batch by itself.
2. Build a lookup using original node UUID and original instance index. The current `InstallStone` filters to `selected` before calculating its batch seed; therefore a selected-array index is **not** the manifest index. Obtain original identity before filtering, or map the original instance object to its index. Preserve existing selection/chunking and source seed for every nonremoved item. Omit matched instances inside the existing batch regeneration loop before `AppendStone`.
3. Expected omission counts: 90 risers in the stone material, 90 treads and 98 original lips in the floor material, total 278. Some source lips were already suppressed by `AppendStone`; the removal contract refers to original input components, not the previous native visible triangle count. Support, sanctuary landing, cheek wall, rubble and portal instances are absent from the manifest.
4. Import `stairs-v11-mesh.json` using the existing native mesh reader. Positions and normals are **Unity world coordinates**. Create a new identity-transform GameObject and apply one stone material to the entire mesh. Do not apply a second basis conversion, source instance transform, or separate top/riser material. `colors` contains quiet neutral per-stone variation for detail UV variation and close base colors.
5. The parent controls the material. Recommended: new material cloned through Editor API with a neutral stone tint shared by top and front, photographic maps retained, wetness still gated by upward normal. This mesh should receive normal stone lighting. Its raised treads are not part of the ground shallow-water plane. Review whether a separate-water keyword is appropriate rather than inheriting it accidentally from the courtyard floor material.
6. Keep the existing ten dark supports. New closed stones occupy the original flight envelope with small authored nose wear; supports stay behind/under them. Compare their contacts in native full, zoom and orbit captures before accepting. The collision/navigation system retains the existing steps/flight contract; inspect movement over the flight if it is reachable.

`preview-before-clay.png` reconstructs the original bridge components with preserved V7 source meshes, under neutral clay. Native candidate36 used V8 for risers, so tiny before chips can differ. The important assembly/joint contrast is unchanged. `preview-after-clay.png` uses exactly the same camera/light/material. These previews establish authored geometry only, not native scene color, lighting, frame rate, or user adoption.
