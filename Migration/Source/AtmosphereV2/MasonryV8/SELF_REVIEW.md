# Masonry v8 architecture assets

Delivery is the eight JSON files directly in this directory: `masonry-v8-0.json` through `masonry-v8-5.json`, and `facade-v8-0.json` through `facade-v8-1.json`. `masonry-v8.blend` retains the authored derivatives and identical-camera inspection setup. The `attempt-*` directories preserve earlier visual attempts and are not the delivery.

The source is the existing `stone-v7/runtime/stone-v7-runtime.blend` masonry sculpt. No floor mesh is modified. Each derivative retains source face relief and fissures, adds a restrained asymmetric 1.2–1.8 cm normalized face concavity, and receives two finite angular edge losses plus a broad open planar corner spall. Chisel depths are 62% of the raw depth parameters in the QA report. The planar corner normals and loss distances are explicitly authored per variant in the build script. This interrupts selected projecting shoulders rather than beveling the entire perimeter.

The six variants have different local damage: top-left loss with opposite side nick; top-right loss plus mid-height edge scar; bottom-left loss plus high side damage; a differently angled wider top-right spall; tall left-edge interruption plus a top-left spall; and bottom-right loss with an opposite upper-edge nick. The two low-cost facade courses derive from the same sculpt and retain distinct top-left/bottom-right corner losses after decimation.

Directly reviewed concept.png, round-23-fixed/full.png, before-inherited-masonry.png and after-masonry-v8.png. The final clay comparison shows open missing corners and different shoulder/edge interruptions across the six variants; the facade pair retains simpler but distinct coarse silhouettes. The quiet face centres remain intact. Several small cut recesses still shade dark at this close inspection scale, so instance variation and material scale should be checked in Unity. These are architecture building blocks, not a full-scene Tier 3 acceptance claim. The inherited broad cuboid bulk remains appropriate for masonry; coursing, per-instance choice and removal of long uninterrupted column extrusions belong to integration.

Two earlier visual attempts passed numeric QA but did not sufficiently interrupt the inherited shoulder: first cuts read as small deep cavities; the second was shallower but still too local. Both are preserved. The delivered third attempt adds visibly broad open corner losses and is the intended candidate for scene evaluation.

Triangle counts: masonry variants 0/1/2/3/5 each 686; variant 4 has 678. Facade variants each 116. Total 4,340. Every asset passes its 700/120 limit. All eight retain exact normalized [-0.5,+0.5] bounds on every Unity axis, finite data, valid arrays and indices, unit normals, zero opposed geometric normals, zero subprecision triangles, and closed surfaces after welding normal seams.

Exports are already in the same Unity basis as v7: position/normal (x,y,z) becomes (-x,z,-y), triangle order becomes (0,2,1), and inspection object transforms are not baked. The new string IDs match filenames. UVs use dominant face projection including newly cut faces.

Only this masonry-v8 directory was written. Hash checks preserve v7 master/runtime blends, ArtSource/public stone sources and the v6 source directory. No Unity files, floor assets, instance transforms, prior evidence outside this directory or Git commits were changed. Blender's deprecated Material.use_nodes warning causes the PowerShell wrapper to report exit 1; the build log confirms both renders, saved blend, MASONRY_V8_COMPLETE and normal Blender quit. Independent export-validation.json contains the final asset QA.
